# Политика безопасности

## Поддерживаемые версии

Проект пока находится в alpha-стадии. Исправления безопасности выпускаются для
актуальной ветки `master`; отдельные долгоживущие ветки версий пока не
поддерживаются.

## Как сообщить об уязвимости

Не публикуйте exploit, реальные credentials или пользовательские данные в
обычном issue. Используйте GitHub Private Vulnerability Reporting в разделе
Security репозитория. Если эта функция недоступна, создайте минимальный issue без
технических деталей и попросите сопровождающего открыть приватный канал.

Полезно приложить:

- затронутую версию или commit hash;
- условия воспроизведения;
- ожидаемое и фактическое поведение;
- оценку возможного влияния;
- безопасный proof of concept без реальных секретов и персональных данных.

## Модель угроз и ограничения

Agent Memory предназначен для локального использования или одного доверенного
оператора. Текущая версия не является multi-tenant системой и не предоставляет
ролевую модель доступа.

- SQLite-файл не зашифрован приложением.
- `MEMORY_API_KEY` защищает API одним общим секретом и не заменяет IAM.
- UI и health endpoints не предназначены для прямой публикации в интернет.
- Проверка credentials снижает риск случайного сохранения секрета, но не может
  распознать все возможные форматы.
- При включённых embeddings обычные (`normal`) записи и поисковые запросы могут
  передаваться настроенному внешнему провайдеру. `sensitive` и `secret` записи не
  отправляются.

Для удалённой установки держите сервис на loopback-интерфейсе, используйте SSH
или TLS reverse proxy, firewall, отдельного системного пользователя, права `0600`
для базы и секреты вне репозитория.
